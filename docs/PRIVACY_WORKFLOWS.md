# 隐私流程检查器

在“发布检查 → 隐私流程检查”中声明数据来源、处理顺序和交付用途，检查人员贡献约束、参数来源和发布开销是否相容。只输入字段与配置，无需上传原始记录。可导入、修改、保存流程方案，下载内部检查记录。

这是对有限操作的声明式条件检查，不是流程执行器。通过表示所声明条件在支持的模型内相容；不会执行表格处理、生成噪声、签发发布许可或改变账本。来源声明和预算快照仍需使用者核实，检查结果不能作为外部文件的可信证明。

## 可复现的差异能力

| 场景 | 检查结果 |
| --- | --- |
| 先按人保留最多 3 条，再删除标识，对数值裁剪到 0–10 后求和 | 保留贡献约束，推导增减一个人的全部记录时 L1 敏感度为 30 |
| 先删人员标识，再按人限制贡献 | 定位到限制步骤，给出来源路径和调整顺序建议；下游不能重新变为通过 |
| 用真实数据的最大值选择上界，再声明公开上界 | 来源标为 `private` 时阻断此模型；`unknown` 时返回无法验证。不能只看最终数值是否在范围内 |
| 同一范围已有 ε=0.2，新发布 ε=0.3、0.5 | 在总预算 ε=1 下恰好可容纳；再增加 0.000001 被阻断 |
| 一个发布分成图表和表格两个展示分支 | 两者保留原发布节点，计划开销只计算一次；从原合计发起另一个发布则累计计算 |
| 加密联合合计直接对外提供 | 合计仍是精确输出，不能自动满足此处的按人 DP 发布目标；追加中心化加噪步骤也不会凭空获得可验证的联合发布条件 |

这里检查的是跨步骤依赖和整份计划，原有的两版联查与报表防反推分析实际输入的不同披露风险；三者用途不同。

## 支持的版本 1

完整例子：[有效方案](../examples/privacy-workflow.json)、[过早删除标识](../examples/privacy-workflow-missing-person.json)。根字段固定为 `schema_version`、`kind`、`scope`、`budget`、`sources`、`steps`、`outputs`。重复 JSON 键（包括转义后的重复）、未知字段和类型错误会被拒绝。

全计划只有一个共同保护范围，保护单位为增减一个人的全部记录。最多 8 个来源、32 个步骤、16 个交付目标，每表最多 32 个字段，文档最多 128000 字符。节点编号为 1–64 位 ASCII 字母、数字、连字符或下划线。步骤必须引用先前节点，允许分支，不支持多输入合并、循环或前向引用。

来源允许私有表 `private_table` 和精确联合合计 `exact_joint_total`。私有表声明字段、人员标识及选取规则来源；不能把导入文件自行标成 `dp_report` 绕过检查。`selection_origin` 指方案进入此流程前的选取规则是否独立于当前私有数据，并非声称原始表格公开。

| 操作 | 检查语义 |
| --- | --- |
| `select_fields` | 只保留原有列，不改变记录数量、次序和保留值。删除列不把明细变成公开结果；已经建立的贡献上限继续保留 |
| `bound_person` | 按声明的可靠人员标识，独立地保留每人前 1–32 条；规则须为公开。后续更大的限制不放宽已有上限 |
| `aggregate` | 计数或非负有界整数和；整数值先裁剪到 0–`upper`（上界 1–1000）。敏感度为每人记录上限乘以数值上界，计数上界固定为 1 |
| `dp_release` | 需要可信持有方、已知按人敏感度和公开参数来源；规划使用已有离散计数/整数和发布模型，纯 ε、δ=0。联合精确合计的分布式条件不在支持范围 |
| `postprocess` | 只以本计划已保护的结果制作表格或图表，不读取任何额外私有输入，不重新采样；保留原发布身份 |

未知操作返回 `inconclusive`，其后续步骤无法恢复为有效状态。对外输出必须为本计划中有效的 `dp_report`；内部输出仍需可信持有者保管。这是本版的发布目标限制，不表示其他隐私模型必然无效。

预算以百万分之一 ε 的整数表示，总预算不超过 1000000000 单位，单次发布为 1–10000000 单位。**所有声明的有效新发布步骤都计入规划，包括没有列入最终交付的分支**；不因输出对象不同而假设群体互斥。`postprocess` 和多个交付目标不重复计费。出现阻断或未验证条件时，`estimate_complete=false`，数字只反映已能核对的部分，不能当作完整开销。

## 命令行与接口

```sh
node cli/main.mjs check-workflow examples/privacy-workflow.json reports/workflow-check.json
node cli/main.mjs check-workflow examples/privacy-workflow-missing-person.json reports/workflow-blocked.json
```

输出文件不得已存在。退出码：0 为声明相容，2 为发现阻断条件，3 为无法验证，1 为格式、输入或文件操作错误。2/3 仍写出解释报告；不读取账本、不创建账本、不执行发布。

MoonBit 接口：`check_privacy_workflow(input : String) -> Json raise KitError`。

JavaScript 接口：`checkPrivacyWorkflow(plan)`，见 [适配模块](../runtime/privacy-workflow.mjs)。文件文本应原样传入，保留重复键校验。检查报告有整体状态、逐步状态、数据类型、路径、贡献上限、敏感度、原发布节点和预算估算；输入文件不含原始数据，但字段与范围信息仍可能敏感，报告按内部资料保管。

## 边界与下一步

本节点没有验证实际人员身份、来源声明、原始数据类型或外部程序是否遵守步骤。将私有参数谎报为公开参数、漏报历史发布、给同一群体改名，均不能由声明检查自动发现。预算快照可能过期，实际发布仍须在现有账本事务内重新核对。

尚未执行任意 SQL、多表连接、LDP/CDP 互换、经 DP 选参的自适应组合、PSI 或分布式加噪。模型不覆盖网络元数据和侧信道。后续可逐项增加经过验证的操作适配及执行时核对，不能给任意自定义代码添加“已保护”标签。

证据：[MoonBit 跨目标测试](../workflow_wbtest.mbt)、[分支/预算/失败路径与 CLI 测试](../tests/workflow.test.mjs)、[工作台测试](../tests/workflow-ui.test.mjs)。
