# 分开保管数据的联合统计

参与方将有界整数向量拆成两个加法份额，分别加密给 A、B 两个聚合节点。每个节点只解密自己的份额，等固定名单中全部参与方提交后，输出签名的合计份额。接收方验证两份结果，重建联合总量。MoonBit 实现配置校验、份额算术、模加聚合及重建边界；Node.js crypto 实现加密传输包和签名。

## 可运行流程

`node cli/privacy.mjs --help` 列出相关命令：

1. 每个参与方使用 `aggregate-identity` 建立自己的 Ed25519 身份，私钥只留本地。
2. A、B 分别运行 `init-aggregate-node` 建立独立库和公钥文件。
3. `create-aggregate-task` 固定参与方公钥、两个节点、类别、上界和任务编号；各方核对同一指纹。
4. 两节点分别 `register-aggregate-task`。参与方用 `prepare-aggregate` 生成发给 A、B 的两个加密文件。
5. 节点分别 `accept-aggregate`。全部参与方齐备后才能 `finalize-aggregate`。
6. 接收方 `combine-aggregate` 验签并得到合计报告。

节点也可独立运行 `node scripts/protocol-service.mjs aggregator 节点.sqlite 端口`。`POST /share` 接收 `{packet}`，`POST /finalize` 接收 `{task: 任务指纹}`。它们是本机验证用服务；远程部署的 TLS、运维隔离和密钥分发不在当前实现范围内。

## 协议与状态

份额位于模 2^24 的加法群；安全随机掩码覆盖整个域。3 至 1000 个固定参与方，每人 1 至 16 个整数、每项上界不超过 1000，诚实输入总量不会回绕。单个均匀份额不泄露对应数值，但若两个节点串通并合并单人的份额，就能恢复其输入。

份额使用 AES-256-GCM 加密，随机 AES 密钥使用指定节点的 RSA-OAEP-SHA256 公钥封装。参与方以 Ed25519 签名绑定任务、身份、节点角色及全部密文；节点结果也签名。注册的任务不可就地改换名单、口径或公钥。不同任务有不同指纹。

每个节点的 SQLite 库只接收同一参与方的一份内容，重复提交复用回执，改换份额拒绝；人数不齐不输出合计份额，也不临时缩小名单。节点完整结果持久化后可反复导出。同一任务的原份额必须保留以便重试，不能重新随机拆分后覆盖。

## 明确边界

此版假设参与方和节点按协议执行，至少一个节点不串通。签名防外部冒用和篡改，不证明参与方提交了真实且在范围内的秘密数值；客户端的范围校验不能代替恶意客户端零知识证明。掉线时停止本批次，不实现隐私安全的掉线恢复。

最终输出是精确合计，可能结合其他知识泄露信息，并非差分隐私。固定名单和至少三方并不能阻止跨任务差分攻击；重复、重叠任务仍需权限、预算和发布保护。各方应只将合计交给授权接收者。报告显式标注输出未加差分隐私保护。

## 差异与来源

moon-privacy-budget 的 5c7ceb0 版本 `noisy_secure_aggregate` 接收明文数组并模拟聚合加噪。本模块实际运行两个独立服务，按节点加密份额、认证参与者、绑定批次、等待完整名单、保存并验证签名合计。它不是预算协调器或给明文总和增加噪声的封装。

参考 Prio 对分布式隐私统计的设计，但不移植其源码，不实现其恶意客户端证明，也不宣称达到 Prio 的全部安全性质。
