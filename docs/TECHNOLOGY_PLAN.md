# 隐私工具体系与技术规划

本文件为[项目申报书](APPLICATION.md)的产品与技术补充。长期建设的重点是持续提供实用隐私工具，并让它们在同一套设计和使用方式下协作。技术选型服务于具体工具的用途，阶段安排见[开发路线](ROADMAP.md)。

截至 2026-10-08，已实现有限类别本地随机响应、问卷文件流程、效果评估、显式字段删除与遮盖，以及中心化差分隐私（CDP）计数和预设类别直方图核心。[本地发布账本](RELEASE_LEDGER.md)已支持累计预算、超预算拒绝及结果复用，[真实表格统计](TABLE_STATISTICS.md)已支持字段映射及命令行发布，工作台报告流程尚待接入，见[核心接口和边界](CENTRAL_PRIVACY.md)。通用跨工具衔接、方案切换、字段泛化及 MPC、PSI、HE、ZKP 均属于后续规划。当前工作台提供多个功能入口，不等于下述通用工具体系已完成。

## 面向用户的长期价值

使用者应当能够从“我要完成什么任务、保护哪些信息”出发选择工具，沿用熟悉的操作方式完成处理，并在需求变化时继续使用已有的兼容配置。项目持续建设以下能力：

- **更多实用工具。**围绕问卷、真实数据处理、统计发布和协作分析开发具体功能，每个工具有清楚的输入、结果和适用场景，也能独立使用。
- **一致的使用方式。**不同工具沿用导入、配置、预览、执行和结果查看的共同步骤，用同一套术语解释数据用途、保护范围和统计误差，降低学习成本。
- **可衔接的处理流程。**在输入类型和保护条件满足时，承接已有数据描述、字段规则及处理结果；通过流程模板减少重复导入、重选字段和手工转换格式。
- **按需切换方案。**当用户由单方分析转向多方协作、改变数据留存方式或调整输出用途时，迁移仍适用的配置，说明差异与所需补充项。
- **持续扩展。**为新增工具约定配置、结果与能力说明格式，复用已有交互和校验，让更多功能加入后仍保持一致的使用体验。

## 实用工具与方案规划

| 使用者要完成的任务 | 工具或方案 | 在统一体系中的衔接方式 |
| --- | --- | --- |
| 收集群体意见并保护回答 | 隐私问卷、样本量与效果评估 | 将评估得到的兼容参数带入问卷配置，沿用统一的报告说明 |
| 整理已掌握或收集的真实数据 | 字段删除、遮盖、年龄分段和日期降精度 | 复用字段规则与数据描述，检查处理结果能否用于后续统计 |
| 向他人提供分析结果 | 隐私统计报告、应用统计接入 | 统一统计口径、贡献限制及发布记录，便于复用报告模板 |
| 多个团队共同开展分析 | 联合汇总、样本重叠核对、联合报告 | 在适配条件满足时沿用统计配置，增加参与方和结果权限设置 |
| 委托外部计算并核对输入条件 | 加密数据委托分析、隐私输入校验 | 按需接入委托或验证步骤，补充密钥与证明要求，统一展示结果 |

这些工具可独立使用，也可组成经过验证的方案。例如，“字段处理 → 隐私统计报告”适合单个数据持有者；“样本重叠核对 → 联合统计 → 受保护报告”面向多方合作。每个模板须明确能承接哪些输入，不能仅凭文件格式相同就连接任意工具。

## 工具衔接与方案切换约定

拟由统一任务配置保存数据描述、字段规则、统计口径、执行角色、输出用途和必要的处理记录。复用以配置与用户授权的数据引用为主，不因启用新工具而默认复制完整原始数据；需要额外存储或外部传输时，说明用途与范围。

切换工具或方案时，先检查输入类型、数据处理历史、贡献限制、信任关系和输出权限，再展示可保留的配置、需要补充的信息及不兼容原因。已删除的数据不能通过切换恢复，受保护回答也不能直接当作原始答案处理；字段处理影响后续统计条件时，应重新验证贡献限制与查询敏感度。

不同工具应携带并继续核算同一保护对象和数据来源下仍适用的隐私开销。更换工具或后端不能清空历史预算，也不能在用户不知情时转为明文计算或扩大结果开放范围。新的保护条件不满足时，保留已有任务并提示所需调整。

使用体验按完整任务验收：比较重复导入次数、字段重新配置次数、手工转换步骤和完成时间，记录用户在哪些地方需要额外理解或求助。各指标以实际测试为准，不预设已达到的改善幅度。

## 支撑工具的技术选择

| 技术 | 拟解决的实际问题 | 首个可交付能力 | 保护边界与取舍 |
| --- | --- | --- | --- |
| 数据最小化与字段泛化 | 持有真实数据，但不需要保留全部敏感信息 | 删除不必要字段，后续增加年龄分段、日期降精度与规则预览 | 保留字段及其关联仍可能识别人；泛化不是完全匿名保证 |
| 本地差分隐私（LDP） | 组织者需要群体意见，参与者希望保护具体回答 | 本地随机化有限选项回答，估计群体比例 | 依赖可信客户端与安全随机源；不隐藏参与事实和传送身份 |
| 中心化差分隐私（CDP） | 数据持有者需要对外发布分析结果 | 有界贡献的计数、公开预设类别直方图与发布预算 | 原始数据持有方受信；逐次发布需组合核算，不能任意加噪即宣称有效 |
| 安全多方计算（MPC），优先 | 多个团队不交换原始明细，但要计算共同指标 | 基于秘密分享的安全求和、计数 | 需声明半诚实或恶意模型、串通阈值及退出行为；精确总量仍可能泄露信息 |
| 隐私集合求交（PSI），优先 | 不集中双方名单，核对样本重叠 | 先支持交集数量，再评估交集上的指标聚合 | 普通 PSI 会揭示交集成员；数量输出也可能敏感，需约束重复查询和结果开放 |
| 同态加密（HE），按需 | 一个数据持有者希望委托外部计算，又不交付明文 | 密文求和、计数，由指定密钥持有者解密 | 加密计算不自动验证结果正确性；密钥持有者与计算方的信任关系必须明确 |
| 零知识证明（ZKP），探索 | 验证秘密输入符合计算约定，又不揭示具体值 | 对已承诺输入进行范围与一致性证明 | 证明的是约定关系，不证明现实数据真实，也不自动解决重复身份 |

MPC 与差分隐私的互补关系参考 [NIST 的技术说明](https://www.nist.gov/blogs/cybersecurity-insights/privacy-enhancing-cryptography-complement-differential-privacy)；集合运算与证明能力分别参考 [NIST PSI](https://csrc.nist.gov/projects/pec/psi) 和 [NIST ZKP](https://csrc.nist.gov/projects/pec/zkproof)。上述任务拆分和实施优先级是本项目的设计选择。

## 优先打通的协同分析流程

以多个课题组各自持有的既有调查数据为例，原始明细保留在各组环境中。拟采用以下流程：

1. **共同确定任务。**约定统计对象、每人贡献上限、类别范围、结果接收者，以及是否允许同一个人出现在多个数据源中。
2. **在本地整理输入。**去掉任务不需要的字段，核对统计口径。统计去重人数前，先确认各方样本是否重叠；存在重复样本时，确定去重或全局贡献约束方案。
3. **按需求选择协议。**只需汇总时使用 MPC；只需知道样本重叠规模时选用仅返回数量的集合运算。拟评估的首个 MPC 原型采用三计算方、半诚实且至多一方被腐化的模型，参与方及部署关系必须写入配置。
4. **控制结果开放。**需要保护发布统计时，在受保护的计算流程内完成噪声生成，再向指定接收者开放结果；避免先公开精确聚合值或交集数量，再补做隐私处理。
5. **生成报告。**记录任务版本、保护单位、预算消耗、误差说明与成本，不包含原始答案、秘密份额、密钥或可还原噪声的随机种子。

安全求和原型和“联合差分隐私报告”分阶段验收。后者需要单独论证分布式随机数、噪声采样、协议中止、重复查询和跨方贡献限制。测试结果用于检查实现，不能替代密码协议的安全论证。MPC 的参与方也可能从自己的输入和允许获得的输出推断信息，这一边界必须在报告中说明。

隐私求交优先使用数量输出，是因为本项目首先需要判断样本重叠，而非取得对方成员名单；需要去重后的联合统计时，另行设计私有集合运算或联结协议。普通标识符哈希不能作为 PSI 的替代实现，交集规模与集合长度的可见性也要纳入协议评估。

## 同态加密与零知识证明的接入条件

同态加密优先用于单个数据持有者的有限算术委托任务。先以 [Microsoft SEAL](https://github.com/microsoft/SEAL) 等后端评估有界整数编码、密文求和、解密正确性与资源开销，不默认转换整库或引入常驻副本。多密钥、阈值解密与复杂查询属于独立后续任务。若可信数据持有者解密后再发布分析，可衔接 CDP；若结果接收者也不应看到精确值，则必须在其解密前落实相应输出保护。

零知识证明先围绕一个明确约束开展验证，例如证明提交的计数处于公开区间，且证明绑定到本次计算实际使用的密文或秘密份额。先评估证明生成时间、验证时间、证明大小与参数设置要求，再决定接入方式。范围证明不能证明没有漏报、造假或重复计数；完整的恶意安全需要结合所用协议设计。

## MoonBit 的职责与可复用接口

拟由 MoonBit 维护任务模型、输入规则、机制参数、贡献约束、预算及结果格式；工作台提供“保护回答”“处理真实数据”“联合统计”“发布报告”等任务入口。基础 DP 算子继续独立实现，密码计算通过明确的宿主或进程接口对接候选后端，具体接口方式经原型验证后确定。

配置需要分别记录隐私保护单位、DP 参数与发布开销，以及密码协议、安全模型和输出权限。密码安全参数不能换算成 ε，也不能用统一的“安全等级”替代这些差异。后端必须声明支持的算子、数值范围、执行环境及泄露边界；不满足条件时拒绝任务，不能静默改用明文计算。

这使问卷和联合统计能够复用任务描述、贡献限制、结果解释与验证数据。项目的技术价值在于将这些约束落实到可运行流程，便于开发者在明确的保护边界内复用。

## 选型依据与评测安排

- **优先 MPC 与 PSI：**直接扩展现有问卷和统计场景，分别解决分散数据的联合汇总与样本重叠问题。MP-SPDZ 作为协议和成本比较候选，其安全模型与审查状态见[参考资料](REFERENCES.md)。
- **按需求推进 HE 与 ZKP：**分别补足委托计算和输入验证；先明确调用方、密钥归属、证明目标与成本，再纳入常用工作流程。
- **保留扩展空间：**联邦学习、可信执行环境和隐私信息检索暂不列为近期交付目标；待出现模型训练、特定部署或隐私查询需求后另行选型。
- **评测标准：**用合成数据比较正确性、误差、通信量、运行时间、峰值内存与额外存储；记录输入规模、参数、硬件和协议版本。性能测试与安全分析分别报告，未测指标不填写预估成绩。

基础工程还需逐步完善传输认证、访问控制、密钥管理与日志最小化。这些措施与隐私算法共同形成保护范围。参考资料和候选后端尚不构成运行时依赖；正式接入时锁定版本、保留许可及来源，并接受相应审查。
