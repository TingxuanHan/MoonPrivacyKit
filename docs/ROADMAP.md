# 开发路线

长期目标是持续增加实用隐私工具，让用户通过统一的中文工作台、配置约定与开发接口按需求选用，只有在条件相容时才组合或切换。当前版本为可运行的本地原型，不是生产安全认证。

## 已完成的基础

原有隐私问卷、逐题精度评估、字段删除/遮盖/年龄日期泛化、文件模板、中心化计数/直方图、SQLite 发布预算、并发重试恢复及离线报告均保留。模板与字段处理的受限统计衔接继续有效，导出已有报告不重新采样或扣费。

## 下一阶段：把已验证工具用好

2026-10-18 新增[隐私合成数据首版](SYNTHETIC_DATA.md)：公开分类域和关系树、按人贡献校验、一次受保护测量、条件抽样、原子保存与重复导出；工作台和 CLI 均已接入。当前没有自动选树、连续数值模型或完整 MST 移植。与 MoonBit 预算/脱敏库及确定性合成测试数据的区别见[生态定位](ECOSYSTEM_POSITIONING.md)。

已完成[隐私流程检查器](PRIVACY_WORKFLOWS.md)：五类步骤的声明检查、分支约束传播、参数来源、共同范围预算规划和精确/受保护输出区分；提供工作台与 CLI。其作用是发布前检查，尚不执行计划或验证来源真实性。

1. 收集真实使用反馈，完善任务选择向导；在有限流程检查基础上逐项增加有验证依据的适配，保留可独立执行的入口。
2. 对报表求解和候选比较做规模评测，提供中断与进度，增加区间/四舍五入约束前补齐相应数学模型。
3. 完善匿名资格的实际分发、网络与日志最小化、独立部署配置；不把当前回环服务当作公网系统。
4. 增加联合计算的故障恢复与部署检查；仍需固定同一任务和参与集合，不能为“成功出结果”静默改成子集。
5. 在已有精确预算权威下评估更多上游机制；只有随机源、保护单位、数值精度和组合语义均通过验证后才开放切换。

下一开发节点优先评估合成数据的带预算关系选择与模型一致性拟合，核对 SmartNoise MST 等可迁移代码的文件级许可，并先明确保护单位、选树开销和可验证的效用指标。当前公开树基线作为可运行参照保留。固定周期统计看板列为后续候选，需明确跨周期贡献和补录规则；这些扩展均尚未实现。

## 后续 4–6 个月：受保护的协作分析

优先开发样本重叠规模核对（PSI-cardinality）和联合受保护报告。当前双聚合器的精确合计不提供 DP；增加分布式加噪需要重新设计预算、噪声生成、跨方重复贡献和结果开放顺序，不能简单给当前输出加噪就宣称全链条安全。

增加经验证的流程模板：整理数据 → 受保护发布，或确认共同样本 → 联合计算 → 受保护报告。模板明确哪些信息属于公开先验、哪些由私有数据决定，保留相关累计开销；不兼容时拒绝衔接并说明原因。

## 长期扩展

根据实际任务评估加密委托分析、输入范围证明、更多统计任务和数据连接器。HE、PSI 和零知识证明目前未实现。新增工具必须有独立场景、维护成本和验收标准。外部安全审计、恶意参与者安全、身份与网络元数据隔离、可持续多方预算管理及生产部署均需单独完成。

不把私有风险指标当作公开报告，也不将字段处理、k-分组检查或精确加密计算称为完全匿名。未来改动继续以可验证节点提交。
