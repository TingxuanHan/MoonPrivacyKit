# 既有项目关系与应用扩展范围

核对日期：2026-10-16。本文补充[项目申报书](APPLICATION.md)，说明已有能力、实际依赖状态、应用层贡献和下一步接入范围。

## 定位与当前关系

MoonPrivacyKit 的参赛重点调整为隐私任务的应用扩展，重点新增处理方案比较器与跨版本联合检查。差分隐私机制、隐私预算管理、敏感信息检测和脱敏已有 MoonBit 实现，不能将这些能力或其简单集合视为本项目的原创贡献。现有问卷、工具衔接和报告流程作为基础，两个新增分析工具的范围见[具体功能与验收设计](PRIVACY_PLANNING_TOOLS.md)。

当前原型的模块声明 [moon.mod](../moon.mod) 未依赖下述两库，也不是其分支或整库移植；目前没有引入其实现代码。申报中的“拟复用”指后续适配目标，不表示已经完成接入。保留现有原型用于验证任务流程，并将基础能力复用列为明确的开发与验收项。应用流程代码独立开发不等同于算法原创。

本次只核对公开 README、模块声明和公开接口，未运行上游测试，也未进行第三方安全审计。以下比较用于划分工作范围，不构成上游功能穷尽清单、性能比较或全生态唯一性声明。

## 本月三个交付目标

以下为 2026-10-16 调整后的待开发目标，当前尚未实现。

1. **基础组件适配。**接入 moon_scrub 的扫描与字段处理，以及 moon-privacy-budget 的预算查询与预留生命周期，交付固定版本的最小示例和兼容性测试。扫描结果不含命中原值；记录改写列，保护前导零及原类型。预算侧明确 ε／δ、组合规则、精度和状态转换，建立唯一预算权威；现有 SQLite 发布事务与后端恢复关系验证前，不把两个独立扣费系统串联用于真实发布。
2. **处理方案比较器。**使用预设的有限候选计算准标识组合分组、低于 k 的记录比例、泛化损失和保留比例，按明确约束筛选并说明取舍。以小表穷举验证，不声称算法原创或全局最优，结果仅供可信持有者使用。
3. **跨版本联合检查。**限定同一群体的两版表和可靠私有行对应，比较单版与联合可见字段的分组变化，覆盖“单版满足阈值、联合后不满足”的反例；不具备对应条件时拒绝作结论，不保存额外的原表历史副本。

每个目标均需保留已有问卷、字段处理和统计流程，并验证失败路径。不能验证历史开销等价映射时禁止后端切换，不通过新建账本绕过累计预算。私有数据驱动的候选选择不直接接入原有差分隐私发布保证；详细边界与测试用例见[新增工具设计](PRIVACY_PLANNING_TOOLS.md)。

计划先复用检测和预算接口；不把上游全部算法、任意管道连接、跨后端预算自动迁移或多方计算承诺为本月交付。向导随后根据已验证能力提供入口。新增工具仍需实际开发和验收，本文不作为已完成集成的证明。
