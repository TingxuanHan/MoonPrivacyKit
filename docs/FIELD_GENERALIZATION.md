# 年龄分段与日期降精度

需要保留年龄结构或时间趋势、但不需要精确值时，可以把年龄变成区间，把完整日期保留到月或年。处理规则能与删除、遮盖放在同一份字段配置中，跨 CSV／JSON 复用；处理后的类别可以继续用于差分隐私统计。

这些操作减少明细精度，不保证匿名化。处理结果仍含逐条记录，可能保留人员标识和其他关联信息；不要把它当作受保护的公开统计报告。

## 在工作台使用

1. 进入“文件脱敏”，导入文件，或点击“试用年龄与日期处理”载入虚构示例。
2. 为年龄列选择“年龄分段”，填写事先确定的分段起点；为日期列选择“日期降精度”，选择月份或年份。其他列可继续保留、删除或遮盖。
3. 点击“处理并预览”，复核区间、日期和处理数量，再下载结果。任意年龄或日期无效、缺失或留空时，整份处理停止，不跳过记录、不生成部分结果。修改规则会立即使旧预览失效。
4. 需要统计时保留稳定的人员标识，点击“用此结果继续统计”，沿用相关统计项目。泛化列只出现在类别选项中，不能用作人员标识。
5. 选择年龄类别后，可点击“按分段配置填写类别”，填入配置定义的全部区间，包括未出现在数据中的区间。日期类别需按事先确定的月份或年份范围逐行填写。核对每人贡献上限和本次 ε 后发布。

保存字段配置会一并保存分段起点和日期精度。导入时先检查列名及数据值，再由用户明确应用；不会自动覆盖设置、生成报告或扣减预算。

## 规则与输入范围

| 规则 | 接受的输入 | 示例输出 |
| --- | --- | --- |
| 年龄分段 | 0 至 130 的整数；JSON 可为数值或整数文本，CSV 为整数文本 | 起点 `18,30,45,60`：23 → `18-29`，60 → `60+` |
| 保留月份 | 有效公历日期，格式严格为 `YYYY-MM-DD` | `2024-02-29` → `2024-02` |
| 保留年份 | 同上，仍校验完整日期 | `2024-02-29` → `2024` |

年龄分段起点须为 1 至 130 内严格递增、不重复的整数，共 1 至 32 个。`[18,30,45,60]` 定义 `0-17`、`18-29`、`30-44`、`45-59`、`60+`；末段也只接受输入范围内的年龄，超过 130 会报错。年龄文本不能有空格、符号、小数、指数或前导零，例如 `018` 不接受。不会自动四舍五入、裁剪或填补空值。

日期范围为 `0001-01-01` 至 `9999-12-31`。校验闰年和每月天数，不接受时间戳、时区、斜线格式或空格，也不把无效日期顺延到下个月。JSON 中日期必须是字符串。每条记录都须包含选作泛化的字段；删除、遮盖字段仍可按原有规则缺失。

分段起点、日期精度及统计公开类别应独立于私有记录事先确定。程序不推断实际年龄范围，不从数据提取月份集合。规则按行独立应用，保留行序与记录数量；改变一个人的记录不会改变其他人的泛化结果。

## 模板与版本

完整示例见 [`generalization-template.json`](../examples/generalization-template.json)，虚构数据见 [`generalization.csv`](../examples/generalization.csv)。版本 2 在原有 `keep`、`remove`、`mask` 之外增加：

```json
{ "name": "age", "action": "age", "boundaries": [18, 30, 45, 60] }
```

```json
{ "name": "visit_date", "action": "date", "precision": "month" }
```

每种操作仅接受自身参数；未知参数、重复键或版本不受支持时拒绝。旧版模板继续可用；只含原有操作时，工作台和 SDK 仍导出版本 1。包含泛化规则的模板导出版本 2，不能用于只支持版本 1 的旧程序。`checkRedactionTemplate` 的 `invalid_values` 表示年龄或日期值不符合规则；结果不回显具体值，只供可信持有者复核。

## 命令行与开发接口

先构建，再检查和处理。输出文件及处理记录必须尚不存在。

```sh
node cli/main.mjs check-redaction-template csv examples/generalization.csv examples/generalization-template.json
node cli/main.mjs redact-template csv examples/generalization.csv generalized.csv examples/generalization-template.json
```

处理记录仍只包含数量；确有泛化值时增加 `generalized_values`，表示处理的单元格数量。没有泛化值时省略此字段，原有删除／遮盖处理记录格式不变。

浏览器、命令行及 SDK 使用相同的 MoonBit 校验与处理实现。`prepareRedactionHandoff` 返回的 `eligible_fields` 继续表示未改写的列；新增 `generalized_fields` 描述仅可作类别的列，包含名称、操作、日期精度及公开年龄区间。日期的 `categories` 为空，需调用方指定公开范围。CSV 公式文本化改变列名时，该列仍排除；输出表头冲突会阻止衔接。

Node.js 通过 `publishRedactedRelease` 从原输入和规则重新计算衔接信息，再使用既有账本发布。统计模板的 `unitField` 必须指向未改写的列，`categoryField` 可指向 `age` 或 `visit_date`；字段名保持原样，值已经改变含义。接口用法见[字段配置与统计衔接](FIELD_WORKFLOWS.md)。

重试必须使用原发布编号。映射后的人员、记录顺序、类别编号及统计设置相同，便复用原报告；原始年龄在同一区间内变化、或与本次查询无关的日期变化，不会产生新结果。改变所用类别或人员映射时，同编号请求被拒绝。新编号发布继续累计预算，换模板、换精度或切换工具都不能重置开销。

## 保护边界

年龄段和月份会把不同人的值归为同一类，因此不能代替人员标识，否则按人的贡献限制会失去原意。系统在直接衔接时区分类别和身份，但不能验证原始标识是否真实，或分段规则是否确实独立于私有数据选择。

泛化输出、精确处理数量和兼容性错误仍是可信环境内的信息。需要对外提供统计结果时，使用受控账本发布差分隐私报告；需要导出明细时，另行评估剩余字段和关联带来的识别风险。下载后再单独导入的文件没有可信处理历史，不能据列类型推断身份未被改写。
