# 处理方案比较与两版数据联合检查

2026-10-16 已实现，核心在 planning_tools.mbt，界面在 web/planning-tools.mjs。工作台入口：发布检查 → 处理方案比较 / 两版数据联查。它们是可信持有者的内部分析工具，不是可公开的差分隐私报告。

## 有限候选方案比较

使用者导入 CSV/JSON，指定准标识字段、必须原样保留的字段、k 和 1–64 份已有字段模板。模板可在“文件脱敏”配置后保存。每个候选复用已实现的删除、遮盖、年龄分段、日期降精度，不从私有数据学习边界。

核心按处理后的准标识元组分组，返回最小组大小、唯一记录比例、低于 k 的记录比例、缺失记录数、保留字段/记录比例和规则损失。按记录评价，重复行可能放大组大小，不自动解释为不同人数。空表、嵌套准标识、未知字段、候选重名或超过上限拒绝分析。null 和缺失是不同的可见状态，报告缺失数量。

损失是公开规则的等权指标：keep=0、mask/remove=1，年龄为最大桶宽减一后除以 130（年龄域 0–130），日期 month=0.5、year=0.8。字段等权平均。它不是学习得到的真实效用，也不把不同场景的业务价值强行统一。每列规则同时保留供解释。

可行条件是所有记录分组至少为 k，且 required_unchanged 中的字段保持原样。frontier 返回在可行候选中未被其他方案同时改善风险和损失的集合；同分方案保留输入顺序，不宣称全局最优。用户明确选择后下载处理副本，不自动删除记录、改写原文件或发布结果。

```sh
node cli/main.mjs compare-plans json input.json candidates.json private-comparison.json
```

配置：schema_version=1、quasi_fields 字段数组、required_unchanged 字段数组、k 整数、candidates 字段模板数组。只接受现有模板格式。详见 tests/planning-tools.test.mjs 中的可运行例子。

扫描建议实际复用 moon_scrub 0.5.2，返回列与类型数量；扫描不替代用户的字段决策，也不自动批准任何处理方案。

## 两版数据联合检查

限定同一群体、一人一行、两版共用私有标识，使用者确认接收方可以正确关联。标识不作为可见字段、也不进入报告。重复标识、缺失对应、增删群体或不存在的可见字段拒绝联查。不会猜测身份或保存整份原表历史。

计算两版分别可见的元组与联合元组，比较最小组、唯一/低于 k 的比例、分组变小条数，以及“两版均达标、联合后不达标”条数。例：第一版分组 {1,2}/{3,4}，第二版 {1,3}/{2,4}，各最小组为 2，联合后均为 1。打乱第二版行序不改变结果，同版重复分析不会制造新增风险。

```sh
node cli/main.mjs compare-versions json version1.json json version2.json linkage.json private-review.json
```

配置：schema_version=1、unit_field、left_fields、right_fields、k、assume_linkable=true。两版最多各 10000 行，最多 12 个可见字段，输入限 2 MB。可关联是输入假设，不是现实攻击必然成功的证据。

## 隐私边界与衔接

精确指标、候选选择和处理后的副本均可能包含敏感信息，只供内部使用。界面修改输入会收起旧结果；不写浏览器存储、不调用发布账本、不在后台备份原表。

私有数据决定的方案选择不能直接沿用后续 DP 保证；人工点击确认也不能把该选择变成公开先验。正式 DP 任务必须使用独立于私有选择的预设规则，或另行设计私有选择与预算组合。当前界面不提供从这些评估结果自动转入 DP 发布的按钮。

基础 k 检查和泛化是已有方法，ARX 用作设计参考。相较 MoonSentinel 的单批核验，本项目实现的是有限候选的明确取舍与关联假设下的跨版交叉细分；不是所有重识别攻击的检测器。详见 ECOSYSTEM_POSITIONING.md。
