# 中心化隐私统计：首个开发节点

本节点提供可复用的计数与预设类别直方图核心，以及使用 Web Crypto 的 JavaScript 适配器。真实数据由可信持有者在本地处理，只返回受保护的统计结果。第二个节点已通过[发布账本](RELEASE_LEDGER.md)复用这些接口，后续继续接入统计报告工具和工作台。

本页的核心接口本身不保存状态，每次调用都是一次新发布。需要累计预算约束和重试复用时，应使用发布账本接口；CSV／JSON 表的统计字段映射与工作台入口尚未接入。测试通过不等同于独立安全审计。

## 使用方法

运行 `npm run build` 后，可执行 `node examples/central.mjs` 查看虚构数据示例，也可在 Node.js 中调用：

```js
import { centralCount, centralHistogram } from './runtime/client.mjs';

const unitIds = ['person-a', 'person-a', 'person-b', 'person-c'];
const categoryIds = [0, 1, 1, 2];

const count = centralCount(unitIds, { epsilon: 1, maxContributions: 1 });
const histogram = centralHistogram(unitIds, categoryIds, {
  categoryCount: 3, epsilon: 1, maxContributions: 1,
});
```

`unitIds` 是同一个人稳定一致的本地标识，不写入结果。类别含义及编号必须事先公开确定，例如“满意／一般／不满意”，不能从真实数据提取出现过的类别后直接公开。`categoryIds` 与记录一一对应。

每人按输入顺序最多保留 `maxContributions` 条记录，直方图各类别合计也不能超过这个上限。上限为 1 时，计数对应去重人数；大于 1 时，计数对应限制贡献后的记录数。直方图中，同一人的后续记录可能被舍弃，结果需按此口径解释。

上例发布了两个独立结果，预算按 1 + 1 累计。重复下载或传送应复用返回对象；重新调用会重新取样，并产生新的隐私开销。JavaScript 返回对象及其计数数组被冻结，但仍可序列化保存。

## 输入与结果约定

| 项目 | 支持范围 |
| --- | --- |
| 隐私保护单位 | 一个人，由数据持有者提供稳定标识 |
| 相邻数据集 | 增加或删除一个人的全部记录，其他人的记录及顺序保持不变 |
| 单次输入 | 0 至 100,000 条记录，支持空数据 |
| 人员标识 | 非空字符串，长度不超过 128；不会自动验证现实身份 |
| 类别 | 预先确定的 1 至 256 类，编号为 0 至类别数减 1 |
| 每人贡献上限 C | 1 至 32，作用于整次查询的全部类别 |
| 单次 ε | 0.01 至 8；零预算被拒绝，不回退为精确统计 |
| 输出范围 | 每项计数固定为 0 至 100,000，与本次真实人数无关 |

MoonBit 接口为 `make_central_mechanism`、`central_count` 和 `central_histogram`。低层 JSON 接口 `dispatch_central` 接受 `centralCount` 或 `centralHistogram` 请求；普通 `dispatch` 的 `centralMechanism` 操作用于查看公开参数，不接收真实数据。具体字段见示例和生成的 `pkg.generated.mbti`。

低层接口的随机回调必须在每次调用时独立、均匀地返回 `[0, size)` 内的安全随机整数。它是宿主适配接口，允许测试注入模拟随机源；真实任务应使用 `runtime/client.mjs` 的高层函数，或另行审查宿主随机源。固定种子和恒定回调不能保护真实数据。

计数和直方图共用 `CentralRelease` 结构，包含机制与格式版本、查询种类、保护单位、单次 ε、贡献上限、类别数、公开输出界限、95% 同时误差界及 `counts` 数组。计数数组长度为 1；直方图返回全部预设类别，包括原计数为零的类别。结果没有真实总人数、原始明细、人员标识、被舍弃记录数、噪声值或随机种子。

## 机制与保护依据

整数计数采用双边几何噪声，即离散 Laplace 机制。其整数与向量机制背景参考 [OpenDP 加性噪声说明](https://docs.opendp.org/en/stable/api/user-guide/measurements/additive-noise-mechanisms.html)。以下有理数校准和采样路径是本项目的实现选择，并非移植 OpenDP 实现或宣称发明新算法。

令 M = 2²⁴，t = floor(M × ε / (C + ε)) − 1，p = t/M，q = 1 − p。构造时检查 t 的范围及 C × t/(M − t) ≤ ε。保留一个整数门限单位作为浮点校准的余量；实际采样只比较整数，不使用浮点逆累积分布函数。

未裁剪的整数噪声满足 P(Z = z) = (1 − q)/(1 + q) × q^|z|。每人最多贡献 C 条记录，因此计数的敏感度及直方图的 L1 敏感度均不超过 C。独立地为各类别加入噪声，似然比上界为 q^(−C)，对应：

```text
C × (−ln q) ≤ C × p/(1 − p) ≤ ε
```

在上述相邻关系和独立均匀随机源假设下，统计结果满足所声明 ε 的纯差分隐私。直方图的 ε 作用于整个向量，不需要再乘类别数。本版校准刻意保守，尤其在较大 ε 时可能加入较多噪声；结果中的 `epsilon_upper_bound` 是确定的校准上界，发布记账仍应使用请求的 `epsilon`。

采样先以 t/(2M − t) 的概率输出零噪声，再以相同概率选择正、负方向；非零幅度使用成功率 t/M 的几何试验。走到固定公开边界 0 或 100,000 时，将剩余尾部概率全部映射到该边界，等价于完整采样后裁剪输出。没有截断噪声再重新归一化，也没有按本次真实人数设置输出上限。

宿主通过 Web Crypto 提供 32 位随机字，再使用拒绝采样生成所需范围内的均匀整数，避免直接取模偏差。随机源不可用或抛错时不返回统计结果，不使用 `Math.random` 降级。计算在可信环境中进行，本版没有恒定时间或侧信道保护承诺。

## 误差说明

报告的 `absolute_error_bound` 是所有类别同时成立的 95% 绝对计数误差界，比较对象是限制每人贡献后的精确统计。若类别数为 k、误差半径为 r，则联合尾概率不超过 2k × exp(−p r)。代码取 `ceil(ln(2k/0.05)/p) + 1`，并以公开输出宽度为上限。输出裁剪不会增大相对该精确统计的绝对误差。

该界不包含贡献裁剪相对原始无限制统计的偏差、不诚实输入或抽样偏差。它不是每项输出的精确置信区间，也不承诺小样本一定有可用精度。直方图各项之和不必等于另一次计数发布结果；不要附加真实总人数来“修正”它。

## 与其他工具衔接时的条件

真实数据应先在可信环境内建立保护单位和贡献规则。字段处理若删除了用于识别同一人的唯一信息，后续不能把每一行当作不同的人以绕过上限；可保留仅供本地统计使用的不透明标识，并在发布结果中移除。

调用方要确保同一个人的多条记录使用同一标识，并且预处理不会因一个人的加入或移除而改变其他人的类别或记录。分类规则、贡献上限和公开输出配置不得根据未经保护的数据随意调整后公开。替换一个人的记录、家庭级保护、跨表关联或其他查询口径需要重新分析敏感度。

输入错误、验证日志、耗时和数据规模仅供可信持有者处理，不能直接开放为面向外部的查询服务。本节点只保护成功返回的统计值，不保护持有者已经看到的明细，也不替代原始数据访问控制。

发布账本已接入累计预算拒绝和结果复用，下一节点连接文件统计配置与工作台。切换工具或数据处理方案不得重置同一保护对象仍适用的发布开销。

## 验证

`central_wbtest.mbt` 覆盖贡献上限、删除整个人的敏感度、空数据、输入边界、采样分支，并穷举小域检查噪声分布及相邻概率比。`tests/central.test.mjs` 使用精确整数运算核查预算校准、验证安全随机适配与失效处理，并用固定种子的虚构数据检查噪声矩和同时误差界。

这些检查用于发现实现回归。机制推导、跨目标测试和有限模拟都不能替代完整机器算术证明或独立安全审计。执行方式及实际通过结果见[验证记录](VALIDATION.md)。
